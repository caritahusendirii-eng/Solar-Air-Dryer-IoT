Desain Sistem Aplikasi Solar Dryer IoT

1. Gambaran Umum Sistem

Sistem Solar Dryer IoT adalah platform monitoring dan kontrol pengering surya berbasis Internet of Things (IoT). Sistem ini memungkinkan pengguna memantau suhu & kelembaban dari 10 sensor DHT22 secara real-time, serta mengontrol kecepatan blower BTS7960 melalui dashboard web maupun mobile.

Komponen Utama

Komponen Teknologi Fungsi
Firmware ESP32 + Arduino C++ Membaca sensor, kontrol blower, kirim data
Backend/Database Firebase Realtime Database Penyimpanan & sinkronisasi data real-time
Autentikasi Firebase Authentication Login, session, RBAC
Web Dashboard React 18 + Recharts Monitoring & kontrol via browser
Mobile App (React) React + Capacitor 8 APK Android dari codebase React
Mobile App (Flutter) Flutter + fl_chart Aplikasi mobile native Android
Hosting Web Netlify Deploy dashboard web

3.2 Kontrol Blower (BTS7960 PWM)

Kecepatan (0-100%) → map ke PWM (0-255)
├── speed > 0  → Enable HIGH + ledcWrite(pwmValue)
└── speed == 0 → ledcWrite(0) + Enable LOW (hemat daya)

PWM Config: 5kHz, 8-bit resolution, LEDC channel 0

4. Firmware ESP32 — Alur Kerja

4.1 Sequence Diagram

sequenceDiagram
    participant S as 10x DHT22
    participant E as ESP32
    participant SD as SD Card
    participant RTC as RTC DS3231
    participant FB as Firebase RTDB
    participant D as Dashboard

    Note over E: SETUP (Boot)
    E->>S: Init 10 sensor DHT22
    E->>RTC: Init RTC DS3231 (I2C)
    E->>SD: Init SD Card (SPI)
    E->>FB: WiFi Connect → Firebase Auth
    E->>FB: Set initial blower speed = 0
    E->>FB: Set control_mode = "manual"
    E->>FB: beginStream("/blowers")

    loop Setiap 60 detik
        E->>RTC: Baca timestamp
        E->>S: Baca 10 sensor (suhu + kelembaban)
        E->>E: Hitung rata-rata (avg_t, avg_h)
        E->>FB: SET /sensor_data (JSON detail)
        E->>SD: Append ke /data.csv
        E->>FB: PUSH ke /history (dengan server timestamp)
    end

    D->>FB: User ubah speed blower
    FB-->>E: Stream callback /blowers/blower1/speed
    E->>E: setBlowerSpeed() → PWM output

4.2 Interval & Timing

Aksi Interval Keterangan
Baca Sensor 60.000 ms (1 menit) Baca 10 sensor + kirim ke Firebase
Push History 60.000 ms (1 menit) Simpan ke node /history
Log SD Card Setiap menit unik Cek lastLoggedMinute berbeda
WiFi Reconnect 15.000 ms Auto-check jika WiFi terputus

6.4 Session Management

  • Durasi: 1 jam (3.600.000 ms)
  • Mekanisme: Timestamp disimpan di localStorage → timer setTimeout otomatis logout
  • Presence: /presence/{uid} di-set saat login, onDisconnect().remove() otomatis saat offline

sequenceDiagram
    participant FB as Firebase RTDB
    participant APP as App.jsx
    participant UI as UI Components

    APP->>FB: onValue("/sensor_data")
    FB-->>APP: {avg_t, avg_h, sensor_data[], waktu, tanggal}
    APP->>UI: setSensorData() → SensorCard, IndividualSensorCard

    APP->>FB: onValue("/blowers")
    FB-->>APP: {blower1: {name, speed}, blower2: {...}}
    APP->>UI: setBlowers() → BlowerControl, Fan Status

    APP->>FB: onValue("/history")
    FB-->>APP: [{avg_t, avg_h, sensor_data[], timestamp}, ...]
    APP->>UI: setHistory() → SensorChart, Data Table

    APP->>FB: onValue("/control_mode")
    FB-->>APP: "manual" | "auto"
    APP->>UI: setControlMode() → Mode Switch

6.6 Fitur Export CSV

  • Format: history_sensor_YYYY-MM-DD.csv
  • Kolom: Tanggal, Waktu, Avg T, Avg H, S1-T, S1-H, ..., S10-T, S10-H
  • Web: Blob download via <a> tag
  • Android (Capacitor): Filesystem.writeFile() → Share.share() (native share dialog)

    W->>W: Filter tab berdasarkan role
    W->>FB: SET /presence/{uid} (online)

11. Konektivitas & Error Handling

11.1 Deteksi Online/Offline

Layer Mekanisme Timeout
ESP32 → WiFi WiFi.status() check setiap 15 detik Auto reconnect
ESP32 → Firebase Firebase.ready() check sebelum write Token auto-refresh
Dashboard Bandingkan lastUpdatedAt vs Date.now() 120 detik (2 menit)

11.2 Error Handling pada ESP32

  • Sensor gagal → tampilkan "GAGAL" di Serial, kirim "null" ke Firebase
  • SD Card gagal → lanjut tanpa logging lokal (sdReady = false)
  • WiFi gagal → retry otomatis di background
  • Firebase timeout → retry pada iterasi loop berikutnya

13. Ringkasan Desain

Sistem Solar Dryer IoT merupakan arsitektur 3-tier yang terdiri dari:

  1. Hardware Tier — ESP32 sebagai edge computing device yang membaca 10 sensor, mengontrol blower via PWM, menyimpan log ke SD card, dan berkomunikasi dua arah dengan Firebase.

  2. Cloud Tier — Firebase sebagai backbone yang menyediakan real-time database (sinkronisasi data sensor + perintah kontrol), autentikasi (email/password), dan otorisasi (RBAC 5 level).

  3. Client Tier — Dashboard multi-platform (React Web + Capacitor Android + Flutter Android) yang menyajikan monitoring real-time, kontrol blower, visualisasi grafik, tabel data historis dengan export CSV, dan manajemen user.

Seluruh komunikasi bersifat event-driven — ESP32 menggunakan Firebase stream listener untuk menerima perintah kontrol secara instan, sementara dashboard menggunakan onValue listener untuk menerima update data sensor secara real-time tanpa polling.
